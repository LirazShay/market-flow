# D-020 — Tests-first pyramid with sparse browser checkpoints

Status: Accepted / evolved after the testing-refactor mini-project

Decision:

~~~text
new deterministic behavior
→ define meaningful tests first where practical
→ fast Node unit tests / Fast CI

browser-only semantics or integration boundary
→ Playwright + Chromium at meaningful checkpoints

real provider behavior
→ live verification only when required
~~~

For bug fixes:

~~~text
regression test
→ fix
→ keep the regression test
~~~

For Local History Viewer V1:

- Fast CI is the normal feedback loop.
- Playwright/Chromium is not run automatically for every small implementation push.
- Browser CI is a manual/reusable checkpoint workflow.
- IndexedDB is exercised in real Chromium when transaction/storage semantics matter.
- DOM/BroadcastChannel should use browser implementations where practical.
- MapHeat2 and GetSecuritiesData are mocked in CI with deterministic sanitized fixtures.
- live Leumi checks remain separate and must not put credentials/session state in GitHub Actions.
- tests protect observable/public contracts, not incidental private implementation details.

Authoritative workstream checkpoint policy:

~~~text
scripts/research/market-data/leumi/prototypes/local-history-viewer-v1/tests/TESTING_POLICY.md
~~~

Why:

- deterministic logic gets feedback in milliseconds rather than paying Chromium startup cost;
- browser integration coverage remains strong at boundaries where browser semantics matter;
- CI stays reproducible and independent from private sessions;
- fewer expensive browser runs make iterative development faster without weakening correctness.
