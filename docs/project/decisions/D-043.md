# D-043 — V2 preserves the V1 collection/data contract and exposes three Viewer surfaces

Status: Accepted

## Decision

Local History Viewer V2 is an evolution of the proven V1 market-data flow.

The Browser SQL migration preserves the existing authenticated Leumi collection/data contract unless separate provider evidence explicitly requires a later change.

The intended change boundary is:

~~~text
same proven provider acquisition + complete-cycle validation
→ replace IndexedDB market-history persistence with SQL Authority / DuckDB-Wasm / OPFS
→ add scheduled user SQL
→ preserve two V1-derived Viewer surfaces
→ add one separate SQL Scanner surface
~~~

The three product surfaces are:

1. Current Universe — all securities with latest committed bank data;
2. Security Detail/History — one security plus its persisted history;
3. Dynamic SQL Scanner — user SQL + configurable repeat interval + SQL-driven result grid.

## Collection continuity

Storage migration is not justification to redesign the provider path.

The following remain preserved contracts:

- authenticated page-context collection;
- MapHeat2 dynamic universe;
- proven sequential GetSecuritiesData flow;
- exact complete-cycle validation;
- canonical `String(PaperId or Key)`;
- full raw MapHeat + Security preservation;
- no hardcoded universe size;
- `null != 0 != "" != undefined`;
- no invented provider semantics.

## Viewer meaning

The SQL Scanner is additive.

It must not replace the Current Universe or Security Detail/History surfaces.

After SQL cutover, all three surfaces obtain data through the Runtime Controller / SQL Authority boundary; Viewer clients never become independent DuckDB/OPFS owners.

A scanner row with canonical SecurityId may navigate to the existing security detail surface. No trading/order-execution workflow is introduced by this decision.

## Planning-freeze amendment

D-042 permits a narrow amendment when a material new product requirement changes scope.

This decision uses that mechanism.

It does **not** add a new Work Package or reorder the 42-package graph. The existing owners are sufficient:

~~~text

~~~
