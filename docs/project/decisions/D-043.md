# D-043 — V2 preserves the V1 collection/data contract and exposes three Viewer surfaces

Status: Accepted / amended by D-045 traceability

## Decision

Local History Viewer V2 remains an evolution of the proven V1 market-data flow.

Current product boundary:

~~~text
authenticated Leumi page
→ preserved MapHeat2 + sequential GetSecuritiesData acquisition
→ exact complete-cycle validation
→ loopback WebSocket transport
→ one localhost Node.js service
→ native DuckDB authority
→ Current Universe + Security Detail/History + Dynamic SQL Scanner
~~~

The three product surfaces remain:

1. Current Universe — all securities with latest committed data;
2. Security Detail/History — one security plus its persisted history;
3. Dynamic SQL Scanner — user SQL + configurable repeat interval + SQL-driven result grid.

## Collection continuity

Preserve authentication in the Leumi browser context, MapHeat2 dynamic universe, sequential GetSecuritiesData, canonical `String(PaperId or Key)`, dynamic universe size, exact cycle accounting, full raw MapHeat + Security preservation, `null != 0 != "" != undefined`, and no invented provider semantics.

Incomplete/corrupt cycles do not advance authoritative history.

## Authority boundary

The authenticated page owns provider access and creation of a validated complete-cycle message.

The WebSocket is transport only. It is not durable state and is never a second source of truth.

The localhost Node.js service is the sole target owner of persisted V2 market history and SQL execution after cutover. It owns the DuckDB database and exposes trusted read/query surfaces to local clients.

Viewer/Scanner clients do not write the database directly. Authentication/session material is not copied into the Node service or repository artifacts.
