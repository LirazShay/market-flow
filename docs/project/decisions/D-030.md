# D-030 — OPFS durability uses checkpointed batches and idempotent recovery

Status: Accepted

## Decision

Local History Viewer V2 will treat one origin-scoped DuckDB-Wasm OPFS database as the authoritative local market-history store after cutover.

Market-cycle durable success requires:

~~~text
atomic SQL COMMIT
→ CHECKPOINT
→ acknowledgement
~~~

Every complete-cycle handoff has a stable ingest_token stored UNIQUE in cycle so retry can distinguish not-committed from committed-but-acknowledgement-lost.

## Database identity

~~~text
opfs://market-flow-v2.duckdb
~~~

One dedicated SQL Authority Worker remains the normal owner of the database handle.

## Browser-storage state

Runtime distinguishes persistent origin storage from best-effort storage through the browser Storage API where available.

A denied persistence request does not become a false durability claim. Quota/usage values are estimates only.

## Recovery

On reopen:

- open the same database rather than creating a replacement;
- validate logical schema/readiness;
- migrate only through explicit ordered migrations;
- mark stale running recording sessions/query executions interrupted;
- restore active query state and coalesce missed scheduler ticks;
- reconcile pending ingest_token before retry.

## Checkpoint policy

Explicit CHECKPOINT is required after each successful market-cycle COMMIT before acknowledgement, after durable query/config activation, around schema migration and on graceful shutdown when possible.

Correctness must not depend on graceful browser shutdown.

## Failure boundary

If CHECKPOINT fails after COMMIT, the system does not pretend the transaction rolled back and does not blindly retry.

It enters durability-uncertain and reconciles the ingest_token.

If open/readiness/migration fails, normal startup does not delete/recreate the database.

## Quota boundary

Quota/storage failure blocks further successful recording acknowledgements.

The runtime does not silently delete old history or silently drop new cycles.

Retention requires its own later policy.

## Package-version boundary

A floating DuckDB-Wasm latest/next tag is not acceptable for persistence authority.

Cutover requires an exact pinned artifact and a green real-browser write/CHECKPOINT/reopen regression test.

## Relationship

- D-026: one SQL Authority Worker.
- D-027: relational schema.
- D-028: atomic enriched cycle transaction.
- D-029: query scheduler.
