# D-032 — Viewer is a detachable client of one Runtime Controller

Status: Accepted

## Decision

Local History Viewer V2 will treat Viewer windows as detachable same-origin clients of one Runtime Controller.

Viewer never opens DuckDB/OPFS directly.

Target interaction:

~~~text
Viewer attach/re-attach
→ Runtime Controller bridge
→ full ViewerStateSnapshot
→ lightweight revision notifications
→ Viewer resyncs authoritative state
~~~

Notifications are hints only, never data authority.

## State identity

Each Runtime Controller lifetime exposes:

~~~text
runtimeInstanceId
stateRevision
~~~

Viewer never compares revisions across different runtimeInstanceId values.

## Result delivery

Execution metadata remains persistent, while the bounded latest-success result preview is runtime-memory derived data.

After runtime restart, latest-success metadata may be restored but the old preview is not presented as if it belongs to the new runtime.

Viewer waits for a new successful execution rather than automatically executing SQL merely to reconstruct the preview.

## Latest error vs latest success

Viewer must keep:

~~~text
latest_execution
latest_successful_execution
~~~

distinct.

A newer failed execution does not erase or relabel the previous successful preview.

## Query activation

Viewer owns draft editor state only.

Activation goes through Runtime Controller to SQL Authority.

Multiple Viewers use optimistic concurrency with expectedActiveQueryVersionId so a stale editor cannot silently overwrite a newer activated SQL version.

## Multi-Viewer

Multiple Viewer clients may observe the same runtime without creating extra SQL Workers or OPFS handles.

Closing any/all Viewers does not stop Recorder or scheduler.

The initial UI may still reuse one primary Viewer window; protocol capability does not require a multi-window launcher.

## Missed notifications

Lost notification can make a Viewer temporarily stale but cannot make authoritative runtime/database state incorrect.

Attach, manual sync or a later notification always obtains a fresh ViewerStateSnapshot.

## Relationship

- D-026: one SQL Authority Worker.
- D-029: query execution/result semantics.
- D-031: runtime/browser delivery.
- D-032: Viewer/result-delivery ownership and synchronization.
