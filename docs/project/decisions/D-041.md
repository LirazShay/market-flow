# D-041 — Browser SQL persistence-affecting releases upgrade side-by-side and roll back by preserved snapshot

Status: Accepted

## Decision

Market Flow distinguishes runtime release, DuckDB-Wasm package/core, DuckDB storage compatibility, and Market Flow schema versions.

A runtime-only release with an unchanged persistence tuple may reopen the existing production DB only after read-only compatibility preflight.

Any DuckDB-Wasm/core, storage-compatibility or logical-schema change is a persistence-affecting release and uses a side-by-side candidate database.

## No in-place production migration

The authoritative pre-upgrade DB is CHECKPOINTed, closed and preserved as a rollback snapshot.

The new release migrates/verifies a separate Market-Flow-owned candidate and promotes it only after CHECKPOINT/reopen/invariant verification.

## Storage format policy

Do not request `latest` storage compatibility implicitly.

Keep the tested storage compatibility target stable across engine upgrades unless a deliberate format migration is justified and verified.

## Rollback

Rollback never relies on an older DuckDB engine opening a database already written by a newer engine.

Rollback selects the retained old release + preserved pre-upgrade DB snapshot and preserves the newer DB separately for diagnosis/roll-forward.

## Schema

Schema migrations are ordered, forward-only and candidate-only. Unsupported newer schema blocks older runtime startup; no automatic down migration/reset.
