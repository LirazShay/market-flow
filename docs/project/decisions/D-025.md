# D-025 — Market Flow V2 analytical architecture is Browser-only SQL

Status: Accepted

## Decision

For the current Market Flow V2 analytical migration planning cycle, the target architecture is constrained to:

~~~text
authenticated browser
→ Market Flow collector
→ Browser SQL engine
→ persistent browser SQL database
→ scheduled user-defined SQL
→ results
~~~

A real SQL execution engine is required.

Changing live analytical logic should normally be possible by changing SQL rather than rewriting application logic.

IndexedDB is not the target analytical engine.

localhost, Node, .NET, native DuckDB and other local-server architectures are not active candidates in this planning cycle. They must not receive implementation Issues, benchmark tracks or parallel design merely as contingency.

If future evidence shows Browser SQL cannot satisfy a required product constraint after reasonable browser-side design/optimization, reopening the process boundary requires a new explicit architecture decision.

## Engine status

Browser-only is decided.

The concrete Browser SQL engine is not yet fully selected.

DuckDB-Wasm with persistent browser storage is the leading candidate and must be checked against current official documentation before becoming an implementation commitment.

A materially better browser SQL engine may be considered during research if evidence justifies it.

## Why

- provider authentication already exists in the browser;
- current requirements do not justify moving session/authentication material elsewhere;
- real SQL/JOIN/GROUP BY/HAVING/window experimentation is first-class;
- minimizing moving parts follows KISS;
- a parallel localhost stack would create complexity before a browser limitation is proven;
- V1 already proves long-running authenticated browser collection is viable.

## Consequences

Planning must cover Browser SQL capability, persistence, origin, Worker/WASM loading, CSP/CORS, transaction/isolation semantics, refresh/reopen, memory/quota, background lifecycle, packaging and browser performance.

The current implementation may temporarily retain IndexedDB during migration, but the target architecture must have one unambiguous market-history authority.

V1 remains frozen.

- D-016 remains valid for technology details not fixed here.
- D-021 KISS supports avoiding a local service without demonstrated need.
