# D-024 — Repository self-maintenance is part of every change

Status: Accepted

Decision:

Market Flow does not rely on separate cleanup work to restore repository order after development.

Every meaningful work unit owns the structural consequences of its own change.

Required flow:

~~~text
identify affected owners
→ change implementation/tests/docs
→ update STATUS / SPEC / context / decision / history in the same coherent batch
→ archive historical detail instead of growing HOT/live context
→ remove temporary diagnostics/triggers/artifacts
→ run repository guards
→ finish with no-cleanup debt
~~~

A work unit is not complete while it knowingly leaves:

- stale or duplicated live status;
- conflicting instructions;
- historical detail inside HOT context;
- an abandoned experiment artifact;
- temporary CI/debug scaffolding;
- changed behavior without the owning SPEC/docs;
- a new parallel source of truth when an existing owner should have been updated.

Machine-enforced guards should protect structural invariants where practical.

When a legitimate future requirement needs a new field/file/structure, update the relevant guard deliberately after confirming the existing simpler owner is insufficient.

This decision does not create a separate housekeeping process. It makes repository hygiene part of ordinary implementation.

Why:

- delayed cleanup is easy to forget;
- fresh chats depend on repository structure being trustworthy;
- duplicate/stale context increases AI error probability and token cost;
- small change-local maintenance is cheaper than periodic large reorganizations;
- structural drift is easiest to prevent at the moment it is introduced;
- the approach reinforces KISS, source-of-truth ownership and continuous improvement.
