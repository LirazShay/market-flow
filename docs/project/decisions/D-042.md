## Meaning of freeze

Implementation should execute the existing issue graph rather than reconstruct architecture from chat history.

Planning may be amended only when implementation/live/benchmark evidence invalidates a contract, a material new product requirement changes scope, or a genuine design contradiction is discovered.

Ordinary implementation difficulty is not sufficient reason to reopen architecture.

## Change discipline after freeze

If the plan must reopen:

1. identify the narrowest owning contract/decision;
2. record Verified/Inferred/Unknown evidence;
3. update the owning design/decision;
4. update decomposition and GitHub dependencies/acceptance;
5. update STATUS.json;
6. re-run the relevant verification before progression.

## Source-of-truth boundary

`STATUS.json` remains the only live operational pointer.

GitHub Work Issues are the executable units.

Planning docs/decisions are durable contracts/evidence and must not become duplicate live-status snapshots.
