# D-003 — Adaptive work batches and natural continuation boundaries

Status: Accepted / evolved

Decision:

Implementation scope is chosen by technical coherence and meaningful verification boundaries.

There is no fixed relationship between one chat message and one substep/stage.

When the user writes:

~~~text
תמשיך לשלב הבא
~~~

the agent continues from the authoritative workstream `STATUS.json` / `ROADMAP.md` into the next planned work, but does **not** have to finish the entire numbered stage in that response.

A valid work batch may be:

- part of a substep;
- one complete substep;
- one complete stage;
- adjacent work that forms one coherent implementation + verification unit.

The agent must not skip planned work or jump to an unrelated later stage merely to reduce message count.

After each meaningful batch, keep `STATUS.json` accurate so another chat/agent can resume exactly.

The word:

~~~text
סיימתי
~~~

is reserved for completion of the full planned process/version requested by the user, not for an individual stage, checkpoint or mini-project.

Why:

- engineering boundaries should drive implementation size;
- tests/verification often create better stop points than stage numbers;
- repository state must remain clear and resumable between chats.
