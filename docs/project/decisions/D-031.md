# D-031 — Browser SQL delivery keeps Market Flow self-contained and pins external engine assets

Status: Accepted

## Decision

Local History Viewer V2 will keep Market Flow application/runtime code self-contained in the generated Browser runtime/Bookmarklet while bundling the pinned @duckdb/duckdb-wasm main JavaScript library into that runtime.

The large DuckDB Worker and Wasm engine assets are loaded from exact immutable versioned HTTPS URLs.

Target:

~~~text
generated Bookmarklet
→ authenticated Leumi page
→ capability/CSP preflight
→ Blob SQL Worker
→ exact pinned DuckDB worker asset
→ exact matching DuckDB Wasm asset
→ AsyncDuckDB
→ Leumi-origin OPFS database
~~~

## Why

The current fully self-contained JavaScript Bookmarklet is a good fit for Market Flow application code, but embedding the entire Wasm binary inline would add avoidable packaging cost.

The official DuckDB-Wasm CDN pattern already supports a Blob Worker plus external exact Worker/Wasm assets.

A Blob Worker preserves the creating page origin in the intended browser model, which is required by the Phase I Leumi-origin OPFS authority.

## Engine bundles

The required baseline is single-thread:

~~~text
prefer eh when supported
fallback mvp
coi not required
~~~

Threaded/coi delivery is not part of correctness.

## Versioning

Runtime generation must bind one exact @duckdb/duckdb-wasm package version to one exact matching Worker/Wasm asset set.

Floating latest/next URLs and automatic version fallback are prohibited.

Authority cutover still requires the Phase I write/CHECKPOINT/reopen verification on the exact artifact.

## CSP/capability gate

Recorder must not start until the real page context successfully proves:

- Worker/Blob capability;
- Wasm capability;
- exact pinned engine Worker startup;
- exact pinned Wasm instantiate;
- required OPFS/storage capability;
- database open/recovery readiness.

If CSP/network/browser policy blocks a required capability, startup fails explicitly.

The runtime does not weaken or bypass the bank's policy and does not silently fall back to IndexedDB or another engine/version.

## Runtime ownership

One Runtime Controller creates/reuses one SQL Authority Worker.

Repeated launch must not create a competing OPFS owner.

Provider collection remains in the authenticated page runtime; SQL Worker receives validated market data, not copied session credentials.

## Generated artifacts

Planned outputs:

~~~text
market-flow-v2.runtime.js
market-flow-v2.bookmarklet.txt
market-flow-v2.runtime-manifest.json
~~~

The inspection manifest records the exact engine/build identity and versioned asset URLs. Runtime behavior does not depend on fetching that manifest separately.

## Live verification

Mock Chromium CI can prove generated delivery logic and failure behavior.

Real authenticated-Leumi compatibility for Bookmarklet, blob Worker, remote Worker asset, Wasm compile/fetch and OPFS remains an explicit live-verification gate before cutover.
