# D-039 — Browser SQL analytical work is preemptible and cannot indefinitely block market ingest

Status: Accepted

## Decision

User analytical SQL runs on a dedicated disposable analytics connection inside the single SQL Authority Worker.

Validated market-cycle persistence has strict priority.

When a validated cycle arrives during analytics, the runtime immediately requests analytical preemption and commits the cycle before any later analytical opportunity.

## Execution primitive

User SQL must use a pending/streamed execution path with bounded poll/fetch slices.

Do not use whole-result materializing `query()` as the production primitive for arbitrary user SQL.

Current upstream DuckDB-Wasm exposes pending-query cancellation, but exact behavior must be reverified in the pinned package.

## Stream boundary

Pending-query cancellation and active result-stream abortion are separate capabilities.

If a stream is active, stop further fetches and dispose/recreate the analytical connection using a mechanism proven in the pinned Chromium build.

## Budgets

Production values are benchmark-derived:

~~~text
analytical_max_runtime_ms
analytics_preemption_budget_ms
~~~

A runtime-budget violation cancels and suspends the active query version.

Ingest-priority cancellation does not automatically disable it.

## Failure escalation

If cooperative cancellation/connection disposal cannot release analytics inside the preemption budget, perform controlled Worker terminate/reopen recovery.

Recorder does not acknowledge the waiting cycle until OPFS readiness is proven and the cycle is committed with its original ingest_token.

Only one complete validated cycle may wait for persistence; the next provider cycle does not start while it is waiting.

## Result semantics

Only successful fully consumed results have `row_count_complete=true`.

Cancelled/resource-limited executions may expose a partial count only with `row_count_complete=false` and never replace latest successful result.

## Relationship

- D-029 defines anchored scheduling/no-overlap.
- D-030 defines durable Worker/OPFS recovery.
- D-034 defines performance/headroom gates.
- D-036 defines health/failure precedence.
- D-039 adds preemption/resource isolation so already-running analytics cannot indefinitely starve ingest.
